## 项目

**名称：** Overclock

**一句话介绍：** X Layer 上的每台机器都跑起来，每个设计都得到证明。Overclock 运行一个区块装不下的 TapeOut 电路，并对 FabX 矿机的全部输入逐一检查，而不是抽样；谁在结果上作假，都会被 X Layer 上的单门检查抓住。

## 产品

TapeOut 的 `eval` 和 `step` 在一笔交易内逐门运行电路。每个门约 2.5K gas，一个区块上限 2.1 亿 gas，所以链上能直接运行的电路大约不超过 80,000 个门；需要运行很多拍的机器，远没到这个规模就已经放不下了。我们做了一次普查（[docs/census.md](census.md)）：X Layer 上共有 11,074 个电路，其中 7 个大到一个区块连一次都跑不完，1,754 台状态机里有 1,014 台在一个区块内跑不满 1,000 拍。这些电路由 213 个钱包持有，其中 996 台是两个 FAB-Genisis 处理器上的 FabX 矿机。

Overclock 在同一套协议上做两件事。

**一、让这些机器真正跑起来：Floor（地板）。** Overclock 运行卡住的机器，方式和 Optimistic Rollup 运行交易一样：运营者用逐位精确的 TAP-02 求值器在链下运行，附上保证金声明结果，同时提交一个覆盖本次运行中每根导线取值的 Merkle 根。任何人都可以免费重跑。如果声明有误，合约把分歧缩小到第一根出错的导线，只对照电路链上网表重新检查那一个 NAND、LATCH 或 REF。Floor 是一张实时网格，列出每台卡住的机器和每种矿机形态，按排队 / 运行中 / 已确认 / 已认证着色，每个电路有自己的页面（`#c/<processor>/<id>`），显示它是什么、归谁所有、直接上链与通过 Overclock 各要花多少、全部交易，以及分享链接。持有者查询（`#owner`）可输入任意地址。

**二、证明一个设计确实做到了它声称的事：证书。** FabX 矿机是一个解答 Gate Challenge（门挑战）的电路。FabX 只要矿机通过该挑战 256 个官方测试向量中的 3 到 32 个**抽样**，就把它标记为"已验证"。我们的测试台电路（`src/bench.js`）同时 REF 这台矿机和 FabX 官方的参考电路，遍历每一种输入，并锁存一个"出现过不一致"的标志和第一个出错的输入。这次遍历作为一个 Overclock 任务运行，输入空间之大没有任何区块装得下；最终确认的任务就是证书。目前已有 8 份证书（[docs/certificates/](certificates/)），都是在本地链上签发的（`scripts/certify.js`，不用密钥、不联网），还没有签发到 X Layer 上：

- #54、#1648、#325（GC-001、GC-048、GC-031）：**通过认证**，在全部 2、16、512 种输入上零不一致。
- #2346（GC-094）、#4890（GC-013）、#4897（GC-014）：**未通过**。这三台都被 FabX 在链上标记为已验证。#2346 在官方向量 17、第 4 周期出错；#4890 和 #4897 是只有一个门、恒输出 0 的占位电路，GC-013 上 FabX 的 3 次抽样检查约有 0.82 的概率放过它。
- GC-098（#310、#4832）：**参考电路不可靠**。我们遍历了 262,655 种输入，但 FabX 的官方参考电路和它的全部 256 个向量输出都是 0，通过它们说明不了任何问题；证书如实写明这一点，而不是宣称通过。

**成本：数字。** 在 v2 合约上的本地演示（`npm run demo`）：16×16 棋盘的生命游戏，100 代，1,817,800 个轨迹步，作假者篡改一个 NAND。

**协议如何运作（v2）。**

1. 任何人都可以**发布任务**：指定一个已流片的电路、输入、初始状态、运行拍数和费用。如果电路最坏情况下的单步检查可能超出上限，发布时就会被拒绝。
2. 运营者附上**保证金**声明结果，保证金随费用增长：`bondFor(job) = minBond + fee × bondBps / 10,000`。
3. 有异议的监督者发起**挑战**。声明方展示往下四层的 16 个节点，合约把它们逐层哈希上去核对父节点，挑战方从 16 个里选出一个：181,840 步只需 5 轮，而不是 18 轮；100 亿步只需 9 轮，而不是 34 轮。任意数量的监督者可以并行挑战同一个声明。
4. 合约**只检查那一个门**，然后结算。输家的保证金对半分：一半归赢家，一半归金库，所以作假者即使通过同伙自己结算自己的声明，每次也要损失半份保证金。
5. **强制错误**（Truebit 对"验证者困境"的解法）：运营者时不时故意提交一个错误声明，并事先做出承诺。第一个抓到它的监督者从金库份额里领取奖金，所以即使没人作假，监督者也有收入。
6. 无人挑战的结果会**最终确认**，任何合约都可以读取结果或接收回调。

**为什么必须是 TapeOut。** 欺诈证明需要一个合约能重新执行的"单步"。对 EVM 来说，这花了 Arbitrum 和 Optimism 多年时间。TapeOut 电路由 NAND 门构成，语义逐字节公开、存储在链上且永不改变，所以一个门*就是*那一步。任何流片过的电路，一出现就能以任意规模运行，不需要仪式或重新编译。REF 让嵌套电路变成嵌套争议，LATCH 状态把一拍拍串起来，这正是零知识路线处理不了的有状态场景。（对数字识别网络，AlephTape 的零知识验证更便宜，297K gas，因为他们已经为它做过可信设置仪式。Overclock 覆盖的是其他所有电路。）

**为什么必须上链。** 核心是让陌生人信任一个不是自己算出来的结果。X Layer 上的保证金和罚没机制让这件事变得安全，而证书之所以有分量，正因为它是公开的、任何人都可以挑战。

## 目标用户与触达方式

1. **电路持有者，首先是 FabX 矿机。** 他们想在烧晶体管之前确认设计是对的，也想看到自己的机器以链上放不下的规模跑起来。他们得到每个电路的专属页面，以及一份证书；如果有错，证书会指出具体出错的输入。
2. **机器构建者**：链上 CPU、带内存的游戏、有状态的电路 AI。用已经流片的电路，两笔交易就能运行任意拍数。
3. **使用电路结果的合约和应用**读取 `result(jobId)` 或接收 `onOverclockResult` 回调（`contracts/Machine.sol` 是一个可运行的示例）。
4. **运营者和监督者**：手上有闲置机器的矿工和节点运营者，赚任务费、抓到作假者的保证金，以及强制错误的奖金。两个机器人都内置在命令行工具里。
5. **AI 智能体**，通过 MCP 服务器和 Claude Code 插件：在依赖某个结果之前先验证它、购买算力，或作为有保证金的运营者或监督者运行。

**有多少这样的用户。** [docs/census.md](census.md) 列出了每个处理器、它的持有者，以及一个运行其最大电路的链接：213 个钱包持有那 1,014 台在一个区块内跑不满 1,000 拍的机器。FabX 自己的接口显示它有 6,978 台矿机（11 月 17 日）。

**如何触达。** 普查列出了持有者，所以我们一个一个点名联系：每人收到一条中英文消息，附上自己那个电路的页面链接（电路跑完之后）。先从有卡住机器的七个非 FabX 处理器开始（AlephTape、LoteGate、Covenant、My hero、TAPELIQUID、Nandverse、GateX），然后是 FAB-Genisis 上最大的持有者，再到 FabX 的 Gate Challenge 社区，以及 TapeOut 和 X Layer 的开发者 Telegram 群。只有在持有者看到自己的证书之后，我们才请他们投票。之后是 Demo Day，以及面向智能体用户的 Claude Code 插件市场。我们为每个电路跑的每个任务，都是给下一位持有者看的公开案例。

## 收入模式

**合约中已实现：** 每个任务收取协议费。结果最终确认时，任务费的 `feeBps` 部分进入金库，其余归运营者。v1 部署收取 2%，合约上限为 10%。没有最终确认的任务不收费。在 v2 中，每笔被罚没的保证金还有一半进入金库，用来支付监督者的奖金。

**计划中，尚未经过客户验证：**

- **证书：** 按每次证书收费，按检查的十亿步数定价。矿机持有者在烧晶体管之前先验证，认证过的矿机在电路市场上可能更好卖。
- **托管监督：** 为想让任务被认领、被监督并有正常运行时间保证的团队提供订阅服务。
- **面向智能体的验证结果 API：** 通过 MCP over HTTP 付费使用 `verify_claim` 和结果读取。

"认证过的矿机更好卖"这一说法和所有价格都只是假设。在其他地方陈述之前，我们会先用头五位持有者验证。

**用户为什么付费。** 对这种规模的机器来说，没有可比较的替代方案：直接上链根本发不出去。有基准可比的地方：在 v2 演示中，生命游戏棋盘的诚实路径比直接运行省 17,947 倍 gas；主网上 CPU 跑 10,000 拍省 42,003 倍。费用只需覆盖运营者的两笔交易、挑战期内锁定的保证金，外加一点利润。对证书来说，替代方案只是抽样。

**用户为什么持续付费。** 有状态的机器不会只跑一次：游戏每回合推进一次，CPU 每个程序跑一次，`continueJob` 从上一次的最终状态开始下一个任务。矿机设计一改，持有者就要重新认证。监督者持续监督，因为强制错误即使没人作假也付钱。

## 使用的生态功能

- **TapeOut 的 processor 工厂与晶体管。** 演示通过 TapeOut 自己的合约铸造 NAND 和 LATCH 晶体管并流片电路。Overclock 只接受已注册 TapeOut processor（`isCPU`）上的电路任务，因为争议依赖于 TapeOut 永远不会更改网表。
- **链上网表。** 单步检查直接从 processor 的网表读取门记录。
- **`REF`。** 棋盘 64 次 REF 单元电路，证书的测试台则 REF 矿机和它的参考电路；争议可以深入到被引用的电路内部。
- **LATCH 与 `step`。** 多拍任务携带状态；测试台的计数器是一个 LATCH 寄存器；LATCH 的读和写都是可争议的单步。
- **ERC-6551 电路账户。** 在主网分叉演练中，棋盘电路自己的账户用 `continueJob` 为下一次运行付费，让机器自己持续运行。
- **FabX。** Gate Challenge 的参考电路、官方向量和矿机的认领记录，都从 FabX 的合约和公开接口读取；证书对照的是 FabX 自己的参考电路。
- **X Layer 与 OKX Wallet。** v1 在主网；浏览器里和 MCP 批准页面里都有钱包流程。
- **DeWEB。** 网站是一个不依赖外部字体或脚本的独立文件，`scripts/publish-deweb.js` 会把它存进某个电路自己的容器（已在主网分叉上演练）。尚未发布：需要支付容器费用。
- **MCP 与 Claude Code。** MCP 服务器和插件让智能体可以读取任务、验证声明、发布任务。

## 坦诚说明的局限

- **v2 尚未上线主网。** 主网上的合约是 v1：它早于我们自己审计中的修复，没有所有者，也无法升级，检查时余额为 0 OKB。保证金（0.001 OKB）和挑战期（10 分钟）是演示参数。
- **证书目前是在本地链上签发的，** 还不在 X Layer 上。主网部署钱包余额很小，所以批量运行先在测试网上对照主网电路的镜像进行，等有资金再上主网。
- **Floor 目前大部分还是"排队中"。** 填充它的运行器已经写好并通过测试，但还没有大规模运行；运行索引里目前只有三个主网任务。
- **仅经内部审计，未经独立审计。**
- **强制错误的运行者是受信任的角色。** 由一个地址负责植入强制错误；已承诺的声明不会被罚没，最坏情况受金库池子的余额限制。
- **结果需要等挑战期结束，** 适合批量任务、裁决和证书，不适合即时交易。
- **收入模式是假设。** 2% 的费用已写入合约；证书定价和托管监督还没有经过客户验证。
